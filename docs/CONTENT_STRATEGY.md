# RENYXERA — Content Strategy & Workflow
*PYQs · original practice questions · study material · protected offline access — all branches*
*Written 26 Sep 2026. Budget: ₹0 (free tiers only).*

Content is the product. Users pay for **trustworthy questions, correct answers and clear explanations**; the features only make that content pleasant to use. This document says what content we build, for which branches first, how each piece is made and verified, and how we protect it.

## 3. PYQ workflow (per paper)

1. **Collect.** Download the official question paper and final answer key PDFs from the organizing IIT’s GATE site. Keep the originals in a private `raw/` folder that is never committed.
2. **Extract.** Use Gemini (free tier) with the PDF plus our JSON schema (the `Aggregated_Output.json` shape) → question text in TeX, options, type, marks, and `images_required` tokens.
3. **Crop images.** Crop the figures to `/images/<year-shift>/<q>.png` (the existing ImageResolver naming). Store them on Cloudflare R2 (free up to 10 GB).
4. **Attach the key.** Parse the official answer key into `question_answers`: correct options, NAT ranges, and **all** ranges for “A OR B” answers.
5. **Tag.** An AI proposes subject, topic and difficulty against our syllabus tree; a human accepts or corrects in bulk (spreadsheet review).
6. **Solve.** An AI drafts the solution. **Automatic check:** the draft's final answer must match the official key; if it doesn't, the question goes to a manual queue.
7. **Verify.** A human reviewer (the founder at first, later paid-per-question toppers or campus ambassadors) reviews ~10% at random plus every flagged item.
8. **Publish.** `npm run seed:questions` (to be extended per branch). The public half goes to `questions`/`question_options`; the key goes only to `question_answers`.
9. **Feedback loop.** A “Report an issue” button on every question, and a 24-hour fix target for accepted reports.

**Quality gates (a paper isn't published until all pass):**
- 100% of questions have an answer key.
- 100% of solutions agree with the key.
- 0 unresolved image tokens (the check already exists in the repository diagnostics).
- TeX renders on desktop and mobile.

## 4. Original practice questions workflow (6D)

Goal: questions that feel like GATE but are **our own**, so we can freely own, sell and refresh them every March.

1. **Blueprint.** For each topic, list the concepts GATE actually tests (taken from that topic's PYQs) plus the usual traps.
2. **Generate.** Prompt the model with the concept, the difficulty, the question type, 2–3 PYQs as style examples (not to copy), and our JSON schema. Ask for the answer and a worked solution too.
3. **Check automatically:**
   - For numeric questions, a second independent model call solves the question; accept only if both answers match.
   - Compare against all PYQs and all existing questions (normalized-text similarity) and reject anything above 0.8.
   - Validate against the schema and confirm the TeX renders.
4. **Human review.** Every hard question, plus a sample of easy and medium ones.
5. **Calibrate.** After real attempts, recompute difficulty from the percentage who got it right, and retire questions that are bad or ambiguous.
6. **March refresh.** After each new exam, add the new PYQs, generate about 10% new practice questions in topics that trended, and retire the 10% that perform worst.

**Cost:** Gemini free tier, with batch generation spread across days. A branch is about 4,000 questions → roughly 3–4 weeks of free-tier quota, run by a script with a resume checkpoint.

## 5. Study material workflow (6E)

Per topic:
- a 1–2 page note (concepts, formulas, one worked example, 3 common traps);
- a formula sheet per subject;
- a “PYQ pattern” card listing which concepts appeared in which years (generated from our own tags, which makes this unique data).

The workflow is: an AI drafts from the syllabus and our tagged PYQs, a human edits, the content is stored as Markdown+TeX, and it renders with the app's existing Markdown/MathJax components.

**Never copy** text or diagrams from coaching notes or books. Write original text and redraw diagrams.

## 6. Legal & trust rules

- Official GATE papers are released publicly by the IITs. We reproduce them for practice with attribution (“GATE 20XX, IIT ___”). **Solutions, tags, notes and practice questions are 100% our own.**
- Never scrape a competitor's solutions or questions.
- Show a “Verified” badge only on items that passed human review. Trust is what people pay for.

## 7. Question bank protection (Downloads section)

**The rule:** the question bank is never a file the user can download. Offline content lives **inside the app**.

### Design
1. **Downloads page** (`/downloads`, signed-in users only). The user picks packs (for example “CS – Algorithms PYQs”, “Mock 3”, “DBMS notes”). Each pack shows its size, a progress bar, “Available offline”, and a Remove button.
2. **Storage:**
   - Packs are stored in IndexedDB, **encrypted with AES-GCM** (Web Crypto).
   - The key is fetched per user and device from our server after sign-in and kept only in memory, never in localStorage.
   - The key can be used offline for up to 14 days. After that the device must come online to renew it.
   - Signing out, or removing the device from Active Devices, deletes both the key and the packs.
3. **Answers stay separate.** An answer pack is only downloaded for practice mode. Graded mocks never have answers on the device (step 6).
4. **Rendering:**
   - PDF-style study material is drawn on a `<canvas>`, page by page, with no selectable text and no PDF file in the page.
   - The user sees it inside our viewer only.
5. **Watermark.** A faint diagonal repeated watermark on every page and question: the user's email, user ID and a timestamp. Anyone who leaks screenshots can then be traced.
6. **Friction:**
   - Copy, right-click and print are disabled inside the viewer, and the print stylesheet prints a blank page with “Printing is disabled”.
   - A blur overlay appears when the tab loses focus (visibilitychange), as a deterrent.
   - Rate-limited fetching: a user can't pull more than N packs per day; unusual volume is flagged.
7. **Server side:**
   - Packs are served only through an authenticated API that logs who downloaded what.
   - There is no public static URL for the bank. The current `public/data/Aggregated_Output.json` is **removed in step 6**.

### Honest limit
No website can make content 100% impossible to capture: screenshots and cameras always work. The goal is to:
- make bulk export **hard** (encrypted, canvas-rendered, rate-limited);
- make leaks **traceable** (watermark with user ID);
- make leaks **not worth it**, because our value is updated content, analytics and mocks, not a static dump.

This is also exactly how paid platforms like Unacademy and Kindle work.

### Where it sits in the plan
Build it together with step 6. Removing the static JSON and switching the client to the authenticated API is one change; the Downloads page is added on top of it.
