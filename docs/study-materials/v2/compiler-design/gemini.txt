### Chapter 02 · Top-Down Parsing (`LL(1)`)

#### Lesson 02.1 · Grammar Conditioning: Ambiguity, Left Recursion Elimination & Left Factoring
- **Tag:** `[MUST]` — Foundation for `LL(1)` parsing (`2026_FN_Q28`, `2025_AN_Q51`, `2017_AN_Q46`).
- **Estimated reading time:** 65 minutes.
- **Prerequisites:** Lesson 00.1, TOC Ch 03 (CFGs, Parse Trees).
- **Beginner must-see:** A **Top-Down Parser** builds the parse tree starting from Start Symbol `S` downward, peeking only at the **next 1 word (`LL(1)`)** to guess which production rule to pick — zero backtracking allowed (`2026_FN_Q28(A)` false)! If a rule keeps calling itself at the very front (**Left Recursion**: `E -> E - T`) or two rules start with the same prefix (**Unfactored**: `if E then S...`), the parser either loops forever or can't choose!
- **Finer points:**
  - **Why Ambiguous Grammars NEVER work for `LL(1)` (`2025_AN_Q51`):** Show BOTH `G_1` AND `G_2` (`M -> if E then M else S` has `S` after `else`!) are ambiguous, hence NOT `LL(1)`!
  - **Direct & Indirect Left Recursion Elimination (`2017_AN_Q46`):**
    - Rule `A -> A \alpha | \beta` becomes **`A -> \beta A', A' -> \alpha A' | \epsilon`** (`2017_AN_Q46(C)`!).
    - Indirect `A -> Ba, B -> Ab` order of substitution (`i = 1..n`, substitute `A_j` into `A_i` for `j < i`).
  - **Left Factoring (`2026_FN_Q28(C)`):** `A -> \alpha \beta_1 | \alpha \beta_2` becomes `A -> \alpha A', A' -> \beta_1 | \beta_2`.
- **GATE-level items:** Eliminating left recursion preserving associativity/precedence (`2017_AN_Q46`), `LL(1)` mandatory traits (`2026_FN_Q28`: must be left-factored, non-left-recursive, no backtracking), and dangling-else `G_1, G_2` ambiguity (`2025_AN_Q51`).
- **Diagrams needed:** `STACKFRAME` / `FRAMES` (Top-down parser hanging infinitely on `E -> E - T` vs terminating on `E -> T X, X -> -T X | \epsilon`, `2017_AN_Q46`); `TREE` (Two parse trees for `if b then if b then c else if b then c else c` in `G_2`, `2025_AN_Q51`).
- **Hand traces:** Converting `E -> E - T | T, T -> T + F | F` (`2017_AN_Q46`) and left-factoring dangling-else (`showing S' still conflicts on else`).
- **Common mistakes:** Dropping `\epsilon` or writing `E' -> -T E` without recursion when eliminating left recursion; assuming `G_2` in `2025_AN_Q51` is unambiguous without noticing `else S` instead of `else M`!

#### Lesson 02.2 · `FIRST`, `FOLLOW`, `LL(1)` Table Construction & Conflicts
- **Tag:** `[MUST]` — Core parsing marks every year (`2025_FN_Q46`, `2024_FN_Q61`, `2024_AN_Q51`, `2021_FN_Q36`, `2019_FN_Q13`, `2017_FN_Q13`).
- **Estimated reading time:** 85 minutes.
- **Prerequisites:** Lesson 02.1.
- **Beginner must-see:** How does an `LL(1)` parser pick the right rule in 1 peek? It pre-computes TWO cheat lists for every variable `A`: **`FIRST(A)`** ("which starting terminals can `A` produce?") and **`FOLLOW(A)`** ("if `A` vanishes to `\epsilon`, which terminals are legally allowed to stand right *after* `A`?"). Never put `\epsilon` inside `FOLLOW(A)`, and ALWAYS put `$` in `FOLLOW(S)` (`2025_FN_Q46`)!
- **Finer points:**
  - **Exact `FIRST` Rules (`2025_FN_Q46`, `2024_FN_Q61`):** For `A -> X_1 X_2 ... X_k`, collect `FIRST(X_1) - {\epsilon}`, continue to `X_2` ONLY IF `\epsilon \in FIRST(X_1)`, add `\epsilon` to `FIRST(A)` iff ALL `X_i` are nullable!
  - **Exact `FOLLOW` Rules (`2025_FN_Q46`, `2019_FN_Q13`, `2017_FN_Q13`):**
    1. Put **`$`** in `FOLLOW(S)` (`NEVER in FIRST(S)`!).
    2. For `B -> \alpha A \beta`, add `FIRST(\beta) - {\epsilon}` to `FOLLOW(A)`.
    3. If `\beta = \epsilon` OR `\epsilon \in FIRST(\beta)`, ALSO add `FOLLOW(B)` to `FOLLOW(A)` (`2017_FN_Q13`: `R` nullable so `Follow(Q)` gets `First(S) = {y}` too!).
  - **`LL(1)` Table `M[A, a]` Construction (`2024_AN_Q51`, `2021_FN_Q36`):**
    - Place `A -> \alpha` in `M[A, a]` for every $a \in \text{FIRST}(\alpha)$.
    - If `\epsilon \in \text{FIRST}(\alpha)`, place **`A -> \alpha`** in `M[A, b]` for every **$b \in \text{FOLLOW}(A)$** (incl. `$`)!
    - **Grammar is `LL(1)` iff every cell has $\le 1$ entry** (no `FIRST/FIRST` or `FIRST/FOLLOW` clashes; 3-second eliminator checks ambiguity/left-rec/prefix first!).
- **GATE-level items:** `FIRST`/`FOLLOW` properties (`2025_FN_Q46`), nullable `FOLLOW` chains (`2019_FN_Q13`, `2017_FN_Q13`), reverse-engineering missing productions from `FIRST`/`FOLLOW` (`2024_FN_Q61`), and filling `LL(1)` table cells (`2024_AN_Q51`, `2021_FN_Q36`).
- **Diagrams needed:** `FLOW` (Nullable cascade `P -> xQRS` showing `R -> \epsilon` bridging `First(S)` into `Follow(Q)` + 3-Second `LL(1)` Eliminator); `MATRIX` (Complete `LL(1)` parsing table for `2024_AN_Q51` & `2021_FN_Q36`); `TRACE` (Predictive stack parse of `caab`).
- **Hand traces:** Computing `FOLLOW(B)` (`2019_FN_Q13`), `FOLLOW(Q)` (`2017_FN_Q13`: `{w, y}`), filling `2024_AN_Q51` & `2021_FN_Q36` tables, and reverse-checking `2024_FN_Q61`.
- **Common mistakes:** Putting `\epsilon` inside `FOLLOW(A)` (`2025_FN_Q46(C)`!) or `$` inside `FIRST(S)` (`2025_FN_Q46(B)`!); forgetting `FOLLOW(B)` passes into `FOLLOW(A)` when `B -> \alpha A \beta` has nullable `\beta` (`2017_FN_Q13`); putting `T -> \epsilon` in `FIRST` instead of `FOLLOW(T)` cells (`2024_AN_Q51`, `2021_FN_Q36`).

### Chapter 03 · Bottom-Up Parsing (`LR`, `SLR`, `LALR`, `CLR`)

#### Lesson 03.1 · Shift-Reduce Parsing, Precedence Trees, `LR(0)` Items (`CLOSURE`, `GOTO`) & Conflicts
- **Tag:** `[MUST]` — Heavyweight NAT & MCQ producer (`2026_AN_Q41`, `2024_FN_Q32`, `2024_AN_Q64`, `2022_FN_Q29`, `2021_AN_Q46`, `2020_FN_Q21`, `2019_FN_Q19`, `2019_FN_Q36`, `2018_FN_Q48`).
- **Estimated reading time:** 90 minutes.
- **Prerequisites:** Lesson 02.2.
- **Beginner must-see:** Instead of guessing from `S` downward, a **Bottom-Up (`Shift-Reduce / LR`) Parser** pushes input tokens onto a stack (`Shift`) until the top of the stack matches the RHS of a rule (**Handle**), then collapses it (`Reduce`) — building the parse tree bottom-up, tracing a **Rightmost Derivation in Reverse (`2019_FN_Q19`)**! An **`LR(0)` Item** (`S -> A • CB`) is simply a bookmark dot `•` showing *"how much of this rule is already sitting on top of the stack!"*
- **Finer points:**
  - **Bottom-Up Mechanics (`2024_FN_Q32`, `2020_FN_Q21`, `2019_FN_Q19`):** Shift-Reduce & LR = Bottom-Up; total reductions = internal non-terminal nodes (`2020_FN_Q21`: `7`); viable prefixes.
  - **Precedence & Associativity from Parse Trees (`2018_FN_Q48`):** Operators deeper in the tree have **higher precedence**; left-leaning chain = left-associative, right-leaning chain = right-associative!
  - **Building `LR(0)` Automaton (`CLOSURE` & `GOTO`, `2024_AN_Q64`, `2022_FN_Q29`, `2021_AN_Q46`, `2019_FN_Q36`):**
    1. Augment with `S' -> S`.
    2. `CLOSURE(I)`: whenever dot sits immediately left of non-terminal `B` (`A -> \alpha • B \beta`), add `B -> • \gamma` for every `B`-production until no new items appear!
    3. `GOTO(I, X)`: take all items `[A -> \alpha • X \beta] \in I`, advance dot past `X`, and take `CLOSURE(...)`!
  - **`LR(0)` ACTION Table & Conflicts (`2026_AN_Q41`):** Reduce item `[A -> \alpha •]` puts `Reduce` across ALL terminals -> S/R conflict wherever another item shifts a terminal (`2026_AN_Q41`: 5 S/R conflicts in `I0, I2, I3, I5, I7`!).
- **GATE-level items:** Counting `GOTO`/`CLOSURE` items (`2024_AN_Q64`: `9`, `2022_FN_Q29`: `5`, `2021_AN_Q46`: `8`, `2019_FN_Q36`: `5`), counting `LR(0)` S/R conflicts (`2026_AN_Q41`: `5`), reading precedence/associativity from trees (`2018_FN_Q48`), reduction count (`2020_FN_Q21`: `7`), and RMD-in-reverse (`2019_FN_Q19`).
- **Diagrams needed:** `FRAMES` + `STACKFRAME` (Shift-Reduce stack parsing `aaadbbb` `2020_FN_Q21`); `TREE` (`a#b$c$d#e#f` precedence/associativity tree `2018_FN_Q48`); `GRAPHPIC` (Full `LR(0)` DFA for `2026_AN_Q41` marking all 5 conflict states `I0, I2, I3, I5, I7`).
- **Hand traces:** Computing `GOTO(I0, S)` (`9`, `2024_AN_Q64`), `goto(closure(I0), +)` (`5`, `2022_FN_Q29`), `GOTO(GOTO(I0,<),<)` (`8`, `2021_AN_Q46`), `GOTO(I0, ()` (`5`, `2019_FN_Q36`), and all 9 states of `2026_AN_Q41`!
- **Common mistakes:** Adding `C -> • cC` into `I0` of `2026_AN_Q41` when `C` is NOT right after the dot (`S -> • ACB`, NOT `S -> A • CB`!); forgetting `closure` expands recursively (`S -> • SS` adds ALL `S`-rules + `A, B` rules in `2024_AN_Q64`!); reversing `Leftmost` vs `Rightmost in reverse` (`2019_FN_Q19`!).

#### Lesson 03.2 · `SLR(1)`, `CLR(1)` & `LALR(1)`: Lookaheads, Power Hierarchy & Conflict Traps
- **Tag:** `[MUST]` — High-level discriminator (`2025_AN_Q40`, `2022_FN_Q13`, `2021_FN_Q56`, `2017_AN_Q35`).
- **Estimated reading time:** 85 minutes.
- **Prerequisites:** Lesson 02.2 (`FOLLOW`), Lesson 03.1 (`LR(0)`).
- **Beginner must-see:** `LR(0)` is greedy and stupid — it reduces blindly on EVERY terminal, causing useless conflicts! **`SLR(1)`** fixes most of them by checking `FOLLOW(A)` before reducing; **`CLR(1)`** is even smarter, tracking the *exact* local lookahead symbol `[A -> \alpha •, a]` allowed in that specific state; and **`LALR(1)`** shrinks `CLR(1)`'s giant table down to `SLR`'s compact size by gluing states with matching cores!
- **Finer points:**
  - **`SLR(1)` Table:** Put `Reduce A -> \alpha` ONLY in columns of **`FOLLOW(A)`** (`same state count as LR(0)`!).
  - **`CLR(1)` Items (`[A -> \alpha • \beta, a]`):** In `CLOSURE`, `[B -> \beta • A \gamma, a]` spawns `[A -> • \delta, b]` for every $b \in \text{FIRST}(\gamma a)$!
  - **`LALR(1)` State Merging & The R/R Conflict Trap (`2022_FN_Q13(A)`):**
    - Merging `CLR(1)` states with identical core items (`ignoring lookaheads`) can **NEVER create a Shift-Reduce conflict**, yet **CAN create a new Reduce-Reduce conflict** (`S -> Aa | bAc | Bc | bBa, A -> d, B -> d`!)!
  - **Parser Power Hierarchy (`2025_AN_Q40`, `2022_FN_Q13(D)`, `2021_FN_Q56(S1)`, `2017_AN_Q35`):**
    - `LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ CLR(1) = DCFLs` (`O(n)`), inside `All CFGs (CYK O(n^3), 2021_FN_Q56(S2))`!

### Chapter 06 · Intermediate Code Generation

#### Lesson 06.1 · Intermediate Representations (`AST, 3AC, Quadruples, Triples`), `SSA` & Backpatching
- **Tag:** `[MUST]` — Directly covers `2025_AN_Q21`, `2024_AN_Q48`, `2021_AN_Q22`, `2017_FN_Q16`.
- **Estimated reading time:** 75 minutes.
- **Prerequisites:** Lesson 04.1 (ASTs), C8 (2-D array addressing).
- **Beginner must-see:** Instead of writing 5 separate compilers from C/Rust/Go to x86/ARM/RISC-V (`3 × 3 = 9` compilers!), compilers translate every source language into ONE machine-independent **Intermediate Code (`3-Address Code` / `SSA`)** where every instruction holds at most ONE operator (`t1 = a + b`)! When an `if/while` jump target isn't known yet during a single top-down pass, **Backpatching** leaves the target blank and fills it in later (`2025_AN_Q21`)!
- **Finer points:**
  - **IR vs Helper (`2021_AN_Q22`):** `AST`, `3AC`, `CFG` ARE Intermediate Representations; **Symbol Table is NOT an IR**!
  - **3-Address Code Forms & Representations (`2024_AN_Q48`):**
    - **Quadruples** `(op, arg1, arg2, result)` — easy to optimize/move because results live in named temps `t1, t2`!
    - **Triples** `(op, arg1, arg2)` — saves space by pointing to row indices `(0), (2)` (`x[i] = ...` uses `[]=` and `=[]` ops, `2024_AN_Q48`!), hard to move instructions!
    - **Indirect Triples** — pointer array over Triples (`fixes code motion!`).
  - **Static Single Assignment (`SSA`) (`2017_FN_Q16`):** Every assignment gets a brand-new subscript (`p_3, q_4, p_4, q_5`), merging control paths via `x_3 = \phi(x_1, x_2)`.
  - **1-Pass Backpatching (`2025_AN_Q21`):** `makelist(i)`, `merge(p1, p2)`, `backpatch(p, target)` for BOTH short-circuit Boolean expressions AND `if/while` control flow in 1 pass!
- **GATE-level items:** Identifying non-IR (`Symbol table`, `2021_AN_Q22`), filling Triple table entries (`2024_AN_Q48`), converting 3AC to SSA (`2017_FN_Q16`), and 1-pass backpatching scope (`2025_AN_Q21`).

### Chapter 07 · Local Optimisation

#### Lesson 07.1 · Basic Blocks (`Leaders`), CFGs, Expression DAGs, Loop CSE & Ershov Register Allocation
- **Tag:** `[MUST]` — High-ROI 2-mark NATs (`2025_FN_Q52`, `2024_FN_Q51`, `2021_AN_Q43`, `2021_FN_Q11`, `2017_FN_Q54`).
- **Estimated reading time:** 80 minutes.
- **Prerequisites:** Lesson 06.1.
- **Beginner must-see:** Optimizing across random jumps is messy, so compilers chop 3-Address Code at jump boundaries (**Leaders**) into straight-line chunks (**Basic Blocks**) wired into a **Control Flow Graph (CFG)**! Inside one block, gluing identical sub-expressions into an **Expression DAG** eliminates duplicate math (`2021_FN_Q11`), while **Ershov Numbering** on a tree tells the exact minimum CPU registers needed without spilling (`2017_FN_Q54`)!
- **Finer points:**
  - **The 3 Exact Leader Rules (`2025_FN_Q52`, `2024_FN_Q51`):**
    1. First instruction of the code.
    2. Any instruction that is the **target** of a conditional or unconditional jump (`goto`).
    3. Any instruction immediately **following** a conditional or unconditional jump!
    - Basic Block runs from one Leader up to (not including) the next Leader!
  - **Expression DAG Construction (`2021_FN_Q11`):** Shared leaf nodes (`b, c, 1`), reuse existing op node if operands are identical and un-overwritten (`a = b + c; d = b + c;` share node `+`, `2021_FN_Q11`: `6` nodes!).
  - **Local Optimizations & Loop CSE (`2021_AN_Q43`, `2024_AN_Q17`):** Constant Folding, Copy Propagation, Dead Code Elimination, Strength Reduction, Loop-Invariant Hoisting (`x+3, y->f1, y->f2` hoisted out of loop in `2021_AN_Q43` -> `303` adds, `2` derefs!).
  - **Optimal CodeGen / Ershov Register Allocation (`2017_FN_Q54`):** Leaf memory = `1` (immediate operand = `0` in Load/Store ALU!), internal node = `max(L, R)` if `L != R` else `L + 1`; generate heavier child FIRST!
- **GATE-level items:** Counting basic blocks & largest block size (`2025_FN_Q52`: `6`, `2024_FN_Q51`: `7, 6`), DAG node count (`2021_FN_Q11`: `6`), loop CSE operation/deref count (`2021_AN_Q43`: `303, 2`), and minimum registers without spilling (`2017_FN_Q54`: `2`).
- **Diagrams needed:** `FLOW` + `GRAPHPIC` (`1001..1017` leader markers -> 6-block CFG, `2025_FN_Q52`, and `L1..L15` 7-block CFG, `2024_FN_Q51`); `GRAPHPIC` (6-node DAG for `2021_FN_Q11`); `TREE` (Ershov-numbered expression tree for `(a-1)*(((b+c)/3)+d)`, `2017_FN_Q54`).

### Chapter 08 · Data-Flow Analysis

#### Lesson 08.1 · Live Variable Analysis, Available Expressions (`CSE`), Reaching Definitions & Constant Propagation
- **Tag:** `[MUST]` — Guaranteed 2-mark CFG questions (`2026_FN_Q42`, `2026_AN_Q45`, `2025_FN_Q13`, `2023_FN_Q37`, `2021_AN_Q33`).

- **Prerequisites:** Lesson 07.1 (Basic Blocks, CFGs), Graph coloring (`Ch 06B` DM).
- **Beginner must-see:** Local optimization stops at block walls — **Data-Flow Analysis** tracks facts across the ENTIRE Control Flow Graph (including `if-else` splits and `while` loops)! - **Finer points:**
  - **Statement vs Block Equations (`2021_AN_Q33`):** `OUT(S1) = IN(S2)`; `IN(S) = USE(S) ∪ (OUT(S) - DEF(S))`.
  - **1. Live Variable Analysis (Used for Register Allocation `2025_FN_Q13` & Dead Code Elimination):**
    - **Direction:** **Backward**, **Meet = $\bigcup$** (May-analysis!), `IN[EXIT] = \emptyset`, `IN[B] = USE[B] ∪ (OUT[B] - DEF[B])`, **`OUT[B] = \bigcup_{S \in succ(B)} IN[S]`**.
    - Careful building `USE[B]` (used *before* any definition in `B`) and `DEF[B]` (defined *before* any use, or assigned in `B`)!
    - Iterate backward passes until fixed point (`2026_AN_Q45`, `2023_FN_Q37`).
  - **2. Available Expressions (Used for Global CSE, `2026_FN_Q42`):**
    - **Direction:** **Forward**, **Meet = $\bigcap$** (Must-analysis!), `OUT[ENTRY] = \emptyset`, interior `OUT[B]` initialized to **`U` (ALL expressions!)**, `IN[B] = \bigcap_{P \in pred(B)} OUT[P]`, `OUT[B] = e\_gen[B] \cup (IN[B] - e\_kill[B])`!
    - Expression `x + y` is **redundant** at `B` iff `x + y` appears in `B` (before killing `x` or `y`) AND `x + y ∈ IN[B]`!
  - **3. Reaching Definitions (`Forward, ∪`) & Constant Propagation (`Forward, Meet Lattice: UNDEF > const > NAC`).**
- **GATE-level items:** Global CSE redundant expressions (`2026_FN_Q42`), Live variables at exit of CFG blocks (`2026_AN_Q45`, `2023_FN_Q37`), statement liveness `OUT(S1) = IN(S2)` (`2021_AN_Q33`), and Register Allocation link (`2025_FN_Q13`).
- **Diagrams needed:** `COMPARE` (4-Row Data-Flow Cheat Matrix: `Liveness`, `Available Expr`, `Reaching Defs`, `Constant Prop`); `TRACE` + `GRAPHPIC` (Pass 1 & Pass 2 fixed-point tables for Liveness & Available Expressions on a loop CFG); `GRAPHPIC` (Interference graph built from Live sets -> Register Allocation, `2025_FN_Q13`).
- **Hand traces:** Tracing `USE/DEF` and 2 backward passes of Liveness on a 4-block loop CFG (`2023_FN_Q37` pattern); tracing Forward `Available Expressions` initialized to `U` on a diamond+loop CFG; tracing Constant Propagation lattice `UNDEF -> c -> NAC`.
- **Common mistakes:** Initializing `OUT[B]` to `\emptyset` instead of `U` in `Available Expressions` (kills loop-available expressions!); using `∩` instead of `∪` in Liveness (missing live variables needed on one `if` branch!); putting `a ∈ USE[B]` when `B` computes `a = 5; b = a + 1;` (`a` was defined BEFORE its use inside `B`!).
