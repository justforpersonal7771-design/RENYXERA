### Chapter 00 · OS Foundations: Dual Mode, Interrupts & System Calls *(New Prerequisite Chapter)*

#### Lesson 00.1 · What an OS Does, Dual-Mode Protection, Interrupts & System Calls
- **Tag:** `[MUST]` — Zero-level readers get stuck immediately on `2023_FN_Q23`, `2021_FN_Q60`, `2024_AN_Q12` without knowing User Mode vs Kernel Mode and Syscall vs Library calls.
- **Estimated reading time:** 50 minutes.
- **Prerequisites:** C0 (RAM, CPU, Disk basics) & C1/C6 (C functions).
- **Beginner must-see:** Think of a computer like a bank: **User Programs** are customers standing in the lobby (`User Mode`, `Mode Bit = 1`); **the OS Kernel** is the vault manager behind bulletproof glass (`Kernel Mode`, `Mode Bit = 0`). Customers can count their own pocket cash (`strlen`, `x + y`), yet whenever they want money from the vault (read Disk, allocate new memory page, pause for `sleep()`, create a child `fork()`), they MUST press a buzzer (`System Call / Trap`) to ask the Kernel!
- **Finer points:**
  - OS roles: Resource allocator (CPU, RAM, Disk) & Illusion creator (makes 1 CPU feel like 100, makes scattered RAM look contiguous).
  - **Mode Bit (`1 = User`, `0 = Kernel`):** Privileged instructions (`HALT`, `CLI/STI` disable interrupts, writing Page Table Base Register `PTBR`, direct I/O) are illegal in User Mode (hardware raises trap!).
  - **Interrupts vs Traps vs Exceptions:**
    - Asynchronous Hardware Interrupts (Timer tick, Disk I/O finished).
    - Synchronous Software Trap (intentional System Call `syscall` / `int 0x80`).
    - Synchronous CPU Exceptions (Page Fault `2023_FN_Q23`, Division by Zero, Illegal Memory Write `2024_AN_Q28`).
  - **C Library (`libc`) vs System Calls (`2021_FN_Q60`):**
    - Always enters Kernel: `exit()`, `sleep()`, `fork()`, `read()`, `write()`, `wait()`.
    - Pure User-Space: `strlen()`, `strcpy()`, `abs()`, `sin()`.
    - Cached/Conditional Syscall: `malloc()` (reuses user heap free-list when possible; only calls `brk`/`mmap` when out of heap!) and `printf()` (buffers in user RAM until `\n` or buffer full before calling `write()`!).
- **GATE-level items:** Identifying which actions **always** switch User -> Kernel mode (`2023_FN_Q23`: Page Fault & System Call vs function call & `malloc`), and which C functions **always** invoke syscalls (`2021_FN_Q60`: `exit`, `sleep` vs `malloc`, `strlen`).
- **Diagrams needed:** `MEMORY` / `FLOW` (Dual-Mode Bank/Layer Cake showing Mode Bit flipping `1 -> 0` on Syscall/Page Fault/Timer vs staying `1` on `strlen`/`malloc` hit); `TIMELINE` (Syscall round-trip: User code -> `trap` -> Kernel handler -> `iret` -> User code).
- **Hand traces:** Tracing 5 lines of C (`strlen`, `malloc(10)` cached vs uncached, `sleep(1)`, division by `0`, `exit(0)`) marking `Mode Bit = 1` vs `0`.
- **Common mistakes:** Thinking `malloc()` always makes a syscall (`2021_FN_Q60`, `2023_FN_Q23`); thinking `function call` enters kernel mode; thinking Page Fault stays in user mode.

#### Lesson 01.1 · Process Anatomy, PCB & Process State Transitions
- **Tag:** `[MUST]` — Core foundation tested directly in `2024_FN_Q26`, `2024_AN_Q12`, `2020_FN_Q18`, `2025_FN_Q29`.
- **Estimated reading time:** 55 minutes.
- **Prerequisites:** Lesson 00.1.
- **Beginner must-see:** A **program** is a dead recipe book sitting on Disk; a **process** is a live chef cooking that recipe in RAM! Each process gets its own private kitchen (`Text, Data, BSS, Heap, Stack`) and an ID badge called a **PCB (Process Control Block)** so the OS can pause one chef mid-recipe and switch to another.
- **Finer points:**
  - Memory sections of a process + contents of **PCB** (PID, State, PC, Registers, Stack Pointer, PTBR, Open File list, Scheduling priority).
  - **5-State Model** (`New, Ready, Running, Waiting/Blocked, Terminated`) + **7-State Model** (`Suspended Ready`, `Suspended Blocked` when swapped to disk).
  - Legal vs Illegal transitions (`2024_FN_Q26`, `2020_FN_Q18`):
    - Legal: `Ready <-> Running`, `Running -> Waiting` (blocking syscall / page fault / wait), `Waiting -> Ready` (I/O completes).
    - **ILLEGAL:** `Waiting -> Running` (must wait in Ready Queue!), `Ready -> Waiting` (not even running to request I/O!), `Terminated -> Ready`.
  - **What ALWAYS triggers a Context Switch to non-running (`2024_AN_Q12`):** Blocking syscall (yes!), Page fault (yes!), Disk interrupt for *another* process (NO — resumes P!), Timer interrupt (NO — if P's quantum isn't over or higher-priority doesn't preempt!).
  - **CPU Utilisation formula (`1 - p^n`):** intuitive I/O-wait overlap calculation (`[SHOULD]`).
- **GATE-level items:** Spotting illegal transitions (`2024_FN_Q26`, `2020_FN_Q18`); distinguishing events that *always* preempt P (`2024_AN_Q12`); Process Switch cost (saves PCB + flushes/switches Page Table `PTBR`!).
- **Diagrams needed:** `MEMORY` (Process RAM layout + PCB card); `GRAPHPIC` (5-state & 7-state diagrams with legal green arrows and forbidden red-X arrows).
- **Hand traces:** Tracing `2024_AN_Q12` across 4 events; tracing a process through `New -> Ready -> Running -> Waiting -> Ready -> Terminated`.
- **Common mistakes:** Thinking a blocked process jumps straight from `Waiting` to `Running` when disk finishes (`2020_FN_Q18`, `2024_FN_Q26`); thinking ANY timer interrupt forces a process off the CPU (`2024_AN_Q12(D)`!).

#### Lesson 01.2 · `fork()`, `wait()`, `exec()` & Process Creation Trees
- **Tag:** `[MUST]` — Frequent GATE NAT favourite (`2026_FN_Q63`, `2024_FN_Q53`, `2019_FN_Q29`).
- **Estimated reading time:** 65 minutes.
- **Prerequisites:** Lesson 01.1, C3 (short-circuit `&&`/`||`), C5 (loops `break`/`continue`).
- **Beginner must-see:** Calling `fork()` splits ONE running process into TWO identical twins **from the exact line right after `fork()`**! Only ONE tiny number differs between them: `fork()` returns **`0` inside the brand-new Child** and returns **`child_PID (> 0)` inside the Parent**!
- **Finer points:**
  - $n$ unconditional consecutive `fork()` calls -> $2^n$ total processes = $2^n - 1$ child processes (`2019_FN_Q29`).
  - `fork()` with `if` / `break` / `continue` (`2026_FN_Q63`: only child continues loop, parent breaks out -> linear chain!).
  - `fork()` combined with **`&&` and `||` short-circuiting** (`fork() && fork() || fork()`): evaluate left-to-right using `0` (child = false) vs `>0` (parent = true)!
  - **`wait(NULL)` (`2024_FN_Q53`):** parent pauses until one child exits; does NOT stop child from running loop iterations.
  - **`exec()` family:** replaces current memory image (`Text, Data, Heap, Stack`) with a brand-new program (same PID!), never returns on success!
  - **Zombie** (terminated child waiting for parent's `wait()`) vs **Orphan** (parent died first, adopted by PID 1 `init`) + C `stdout` buffering (`\n` vs no `\n`) finer note!
- **GATE-level items:** Exact `printf` execution counts and child counts for loop-based `fork()` (`2026_FN_Q63`, `2024_FN_Q53`, `2019_FN_Q29`) and boolean short-circuit `fork()`.
- **Diagrams needed:** `CALLTREE` / `TREE` (`fork()` branching trees labelling Parent `>0` and Child `0` at every split, with `break` and `wait(NULL)` markers).
- **Hand traces:** Full process-tree trace for `2026_FN_Q63` (`4` prints), `2024_FN_Q53` (`2+4+8 = 14` prints), `2019_FN_Q29` (`5` forks = `31` children), and `if (fork() || fork()) fork();`.
- **Common mistakes:** Counting parent in `"total child processes created"` (`2^n` instead of `2^n - 1`, `2019_FN_Q29`!); thinking a child starts executing from line 1 of `main()` instead of right after `fork()`; missing `break` only executing in the parent (`2026_FN_Q63`).

#### Lesson 01.3 · Threads (Shared vs Private), User/Kernel Thread Models & IPC
- **Tag:** `[MUST]` — Tested across nearly half of all Process questions (`2024_FN_Q12`, `2023_FN_Q22`, `2021_AN_Q41`, `2017_AN_Q14`, `2017_FN_Q25`).
- **Estimated reading time:** 60 minutes.
- **Prerequisites:** Lesson 01.1, C7 (global vs local stack vs heap).
- **Beginner must-see:** Creating a whole new Process (`fork()`) copies the entire house — slow and heavy! A **Thread** is a lightweight worker INSIDE the same house: all threads in one process share the **same RAM address space (`Code, Global Data, Heap, Open Files`)**, while each thread carries its own private **`Stack, Registers, and Program Counter`**!
- **Finer points:**
  - **What is Shared vs Private (`2024_FN_Q12`, `2023_FN_Q22`, `2017_AN_Q14`, `2017_FN_Q25`):**
    - Shared across threads of SAME process: Address space (PTBR!), Global/Static variables, Heap, Open File Descriptor Table, Signal handlers.
    - Private per thread: Stack (local variables!), Program Counter (PC), General Purpose Registers, Stack Pointer (SP), State.
    - **Separate across DIFFERENT processes (`2021_AN_Q41`):** `P1` and `P2` each get separate global `x`!
  - Why Threads are NOT memory-protected from each other (`2024_FN_Q12(D)`): a wild pointer in Thread 1 can corrupt Thread 2's stack/data!
  - Thread Context Switch vs Process Context Switch (no address space / `PTBR` / TLB switch in same-process thread switch, `2023_FN_Q22(A)`!).
  - **User-Level vs Kernel-Level Threads & Mapping Models (`M:1`, `1:1`, `M:N`):** User-level threads don't need kernel syscalls to switch, YET one blocking syscall blocks the whole process (and can't use multiple CPU cores!).
  - **IPC (`[SHOULD]`):** Shared Memory (fast after setup, needs synchronization!) vs Message Passing (kernel copies data, naturally synchronized) vs Pipes (`fd[0]` read, `fd[1]` write).
- **GATE-level items:** Multi-process + multi-thread variable scope puzzles (`2021_AN_Q41`); exact thread context-switch save list (`2023_FN_Q22`); thread properties MSQs (`2024_FN_Q12`).
- **Diagrams needed:** `MEMORY` (Two processes `P1, P2` each holding 2 threads `T1, T2`: Globals/Heap shared *inside* `P1` only, Stacks private *per thread*, `2021_AN_Q41`); `COMPARE` (User-level vs Kernel-level threads & `1:1` vs `M:1` vs `M:N`).
- **Hand traces:** Tracing `2021_AN_Q41` (`P1` and `P2` each have `x=2`, all threads print `y=1`); testing `2023_FN_Q22` context switch steps.
- **Common mistakes:** Thinking threads share a common stack (`2024_FN_Q12(C)`!) or each thread has its own open-file table (`2024_FN_Q12(B)`!); thinking `P1` and `P2` share global `x` (`2021_AN_Q41`!); thinking threads can ONLY live in kernel space (`2024_FN_Q12(A)`!).

### Chapter 02 · CPU and I/O Scheduling *(Old Ch 03)*

#### Lesson 02.1 · Scheduling Fundamentals, Metrics & Non-Preemptive Policies (`FCFS`, `SJF`)
- **Tag:** `[MUST]` — Foundation for every scheduling calculation (`2026_AN_Q23`, `2026_FN_Q64`, `2021_FN_Q14`, `2021_AN_Q29`, `2023_FN_Q27`).
- **Estimated reading time:** 65 minutes.
- **Prerequisites:** Lesson 01.1 (process states & ready queue).
- **Beginner must-see:** Only ONE process can sit on a single CPU core at any instant! Scheduling is just deciding *who in the Ready Queue gets the CPU chair next* — like a doctor calling patients from a waiting room (`FCFS` = first in line; `SJF` = fastest checkup first!).
- **Finer points:**
  - **The 5 Exact Metrics:** Arrival Time (`AT`), Burst Time (`BT`), Completion Time (`CT`), **Turnaround Time (`TAT = CT - AT`)**, **Waiting Time (`WT = TAT - BT`)**, **Response Time (`First_Run - AT`)**.
  - Optimization goals: Maximize CPU utilization & Throughput; Minimize TAT, WT, Response Time (`2021_AN_Q29(B)` trap!).
  - **Preemptive vs Non-Preemptive (`2026_AN_Q23`):** Why FCFS can NEVER be preemptive (no timer/burst condition interrupts an ongoing FCFS run), whereas Priority/RR/SRTF can be preemptive (requiring timer hardware support, `2021_AN_Q29(D)`).
  - **Convoy Effect** in FCFS + **Starvation Nuance (`2023_FN_Q27`):** Why SJF starves long jobs when short jobs keep arriving, AND why `2023_FN_Q27` counts FCFS as potentially starving (only if a job ahead has an *infinite* CPU burst!).
  - **Optimal Non-Preemptive Avg WT (`2021_FN_Q14`):** Why SJF provably minimizes average waiting time for any given set of non-preemptive jobs at `t = 0`.
- **GATE-level items:** Computing exact average waiting time across staggered arrivals (`2026_FN_Q64`: Actuators & Controllers arriving every 10s vs 11s); spotting FCFS impossibility of preemption (`2026_AN_Q23`) and `2023_FN_Q27` starvation MSQ.
- **Diagrams needed:** `TIMELINE` (Gantt chart matched with a calculation table `PID | AT | BT | CT | TAT | WT`); `COMPARE` (FCFS vs SJF Convoy Effect picture).
- **Hand traces:** Tracing all 10 processes of `2026_FN_Q64` (`Avg WT = 9.5 s`); tracing `2021_FN_Q14` (`12 ms`).
- **Common mistakes:** Forgetting `AT` when computing `TAT = CT - AT` (using `CT` directly!); subtracting `BT` twice; thinking CPU stays busy when `t < next_arrival` (leaving idle gaps out of Gantt chart!).

#### Lesson 02.2 · Preemptive Scheduling (`SRTF`, `Round Robin`, `Priority`) & Ready Queue Ties
- **Tag:** `[MUST]` — Core 2-mark NAT/MCQ generator (`2025_AN_Q26`, `2024_AN_Q54`, `2022_FN_Q42`, `2019_FN_Q51`, `2017_FN_Q34`, `2017_AN_Q57`).

- **Finer points:**

### Chapter 03 · Concurrency and Synchronization *(Old Ch 04)*

#### Lesson 03.1 · Race Conditions, Atomicity & Critical Section Rules (`Peterson`, `TSL`, `CAS`)
- **Tag:** `[MUST]` — Unlocks `2024_FN_Q64`, `2023_FN_Q38`, `2021_FN_Q59`, `2019_FN_Q32`, and every lock problem.
- **Estimated reading time:** 75 minutes.
- **Prerequisites:** Lesson 01.3 (threads sharing globals), Lesson 02.2 (preemptive context switching).
- **Beginner must-see:** Even a tiny line like `X++` is NOT one single step to the CPU — it is THREE steps: **1. Read `X` into register, 2. Add `1`, 3. Write back to `X`**. If a thread gets interrupted between Step 1 and Step 3, another thread's update gets **silently overwritten**!
- **Finer points:**
  - **Atomicity Rule in GATE (`2024_FN_Q64`, `2026_AN_Q51` vs `2021_FN_Q59`, `2019_FN_Q32`):** Real C statements (`counter++`) split into `LOAD / OP / STORE` unless the question explicitly says *"each line executes atomically"*!
  - **Finding Min / Max of Unsynchronized Shared Variable (`2019_FN_Q32`):** Systematic interleaving trick (to minimize: have one thread read low initial value, let others raise it, then wake up late to overwrite low!).
  - **The 3 Critical Section Requirements:**
    1. **Mutual Exclusion** (at most one inside CS).
    2. **Progress** (outside CS cannot block inside; finite selection time — note: NO deadlock!).
    3. **Bounded Waiting** (limit on how many times others cut ahead — NO starvation!).
  - **Software Solutions:** Lock variable (fails ME!), Strict Alternation `turn` (fails Progress!), **Peterson's Algorithm** (`flag[2]`, `turn` — satisfies all 3 for 2 processes on sequential memory!).

#### Lesson 03.2 · Semaphores, Mutexes, Barriers & Output-Order Puzzles
- **Tag:** `[MUST]` — Directly covers `2026_AN_Q51`, `2024_AN_Q44`, `2023_FN_Q38`, `2021_FN_Q59`, `2020_FN_Q38`, `2017_FN_Q61`.

### Chapter 04 · Deadlocks *(Old Ch 01 — Now Placed Safely After Processes & Sync!)*

#### Lesson 04.1 · Deadlock Model, 4 Coffman Conditions, Prevention & RAGs
- **Tag:** `[MUST]` — Free-sample quality foundation (`2026_FN_Q29`, `2025_AN_Q48`, `2022_FN_Q26`).
- **Estimated reading time:** 60 minutes.
- **Prerequisites:** Lesson 01.1, Lesson 03.2 (locks & mutual exclusion).
- **Beginner must-see:** Four thieves sitting in a circle, each gripping one coin in their left hand and refusing to drop it until they grab the coin in the next thief's right hand — nobody can move forever! Deadlock ONLY happens if **ALL FOUR** conditions hold simultaneously; breaking even ONE (**Deadlock Prevention**) makes deadlock impossible!
- **Finer points:**
  - **4 Necessary Conditions (Coffman):** Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait.
  - **Deadlock Prevention (breaking 1 of the 4):**
    - Break Hold & Wait (`2026_FN_Q29(B)`): request all resources up front or drop all before requesting.
    - Break No Preemption: OS takes resource back (`2021_AN_Q13`).
    - Break Circular Wait: number resources $1..m$ and force strictly increasing lock order!
  - **Resource Allocation Graph (RAG):**
    - **Edge Direction Rule (`2026_FN_Q29(C)`):** **`Resource -> Process` = Assignment (held)**; **`Process -> Resource` = Request (waiting)**!
    - **Cycle Rule (`2022_FN_Q26(B)`):**
      - All resources have **1 instance** $\implies$ Cycle **IFF** Deadlock!
      - Any resource has **> 1 instance** $\implies$ Cycle is Necessary ONLY (Wait-For Graph cycle does NOT guarantee deadlock!).
      - Zero request edges (only assignment edges) $\implies$ NO Deadlock (`2022_FN_Q26(D)`)!
  - **Aborting Minimum Processes to Break Deadlock (`2025_AN_Q48`):** Finding ALL directed cycles in a RAG and hitting every cycle.
- **GATE-level items:** Spotting flipped RAG edge definitions & Prevention-vs-Avoidance mix-ups (`2026_FN_Q29`); multi-cycle process termination (`2025_AN_Q48`); single vs multi-instance cycle MSQs (`2022_FN_Q26`).
- **Diagrams needed:** `GRAPHPIC` (RAG with dots inside resource squares showing `R -> P` assignment vs `P -> R` request); `COMPARE` (1-instance cycle = Deadlock vs 2-instance cycle = Safe!); `GRAPHPIC` (4-process 2-cycle RAG from `2025_AN_Q48`).
- **Hand traces:** Tracing `2025_AN_Q48` cycles (`P1-P2-P3` and `P2-P4`); testing all 4 options of `2026_FN_Q29` and `2022_FN_Q26`.
- **Common mistakes:** Flipping RAG edge direction (`P -> R` is request, NOT assignment!, `2026_FN_Q29(C)`); claiming a cycle in a multi-instance wait-for graph always means deadlock (`2022_FN_Q26(B)`); calling Banker's algorithm "Prevention" (`2026_FN_Q29(A)`).

#### Lesson 04.2 · Deadlock Avoidance (Banker's Algorithm), Detection & Pigeonhole Resource Math
- **Tag:** `[MUST]` — Classic NAT & matrix favourite (`2026_FN_Q35`, `2019_FN_Q43`, `2018_FN_Q34`, `2018_FN_Q49`, `2017_AN_Q42`).
- **Estimated reading time:** 75 minutes.
- **Prerequisites:** Lesson 04.1.
- **Beginner must-see:** Instead of banning locks upfront (Prevention), **Deadlock Avoidance (Banker's Algorithm)** acts like a smart bank manager: before lending extra cash, it checks *"Even if every customer immediately demands their full credit limit, is there at least ONE order I can pay off one customer at a time and get all my money back?"*
- **Finer points:**
  - **Safe State vs Unsafe State vs Deadlock (`2026_FN_Q29(D)`, `2022_FN_Q26(C)`):** Safe guarantees no deadlock; **Unsafe does NOT guarantee deadlock** (only means deadlock is *possible* if worst-case requests occur!).
  - **Banker's Safety Algorithm (`2018_FN_Q49`):** `Need = Max - Allocation`, `Work = Available`, repeatedly find unfinished `P_i` with `Need[i] <= Work`, set `Work += Allocation[i]` (`O(m \cdot n^2)`).
  - **Resource-Request Algorithm:** Check `Request <= Need` & `Request <= Available`, tentatively grant, run Safety Check.
  - **Deadlock Detection vs Banker's (`[SHOULD]`):** Detection uses current **`Request`** matrix instead of future `Max`/`Need`!
  - **Pigeonhole Resource Counting (`2026_FN_Q35`, `2018_FN_Q34`, `2019_FN_Q43`):**
    - Minimum resources for deadlock-freedom (`n` processes, max `K_i` each): $\sum_{i=1}^n (K_i - 1) + 1$ (if equal $K$: $n(K - 1) + 1$).
    - Maximum $K$ for guaranteed deadlock-freedom given $R$ instances: solve $n(K - 1) + 1 \le R$ (`2018_FN_Q34`).
    - Freezing everyone else (`2019_FN_Q43`): freeing $X_p + X_q$ still cannot unblock any $k$ if $X_p + X_q < \min(Y_k)$.
- **GATE-level items:** Full 3-resource Banker's matrix check (`2018_FN_Q49`, `2017_AN_Q42`); solving for min `K` (`2026_FN_Q35`) or max `K` (`2018_FN_Q34`) and symbolic condition (`2019_FN_Q43`).
- **Diagrams needed:** `CHEATPIC` (Safe > Unsafe > Deadlock nested target rings + 4-row Prevention/Avoidance/Detection/Recovery comparison); `TRACE` (Full Banker's `Allocation | Max | Need | Work` step table for `2018_FN_Q49`); `MEMORY` (Worst-case hoarding boxes for `n(K-1)+1`).
- **Hand traces:** Tracing `2018_FN_Q49` (`P0 -> P2 -> P1 -> P3` safe!); computing `2026_FN_Q35` (`5*(2-1)+1 = 6`) and `2018_FN_Q34` (`K = 2`).
- **Common mistakes:** Forgetting `Need = Max - Allocation` (using `Max` instead of `Need`!); thinking unsafe = already deadlocked (`2022_FN_Q26(C)`!); being off by 1 on `n(K-1) + 1` vs `n(K-1)`.

#### Lesson 05.2 · Paging Mechanics, Address Translation & Byte vs Word Addressing
- **Tag:** `[MUST]` — Core of the highest-weight OS chapter (`2025_FN_Q14`, `2024_AN_Q28`, `2024_FN_Q50`, `2021_FN_Q31`, `2019_FN_Q42`).
- **Estimated reading time:** 75 minutes.
- **Prerequisites:** Lesson 05.1, binary powers (`2^{10}=1\text{K}, 2^{20}=1\text{M}, 2^{30}=1\text{G}`).
- **Beginner must-see:** Instead of squeezing an entire program into one big hole, **Paging** chops the program into tiny equal-sized pages (e.g. `4 KB`) and RAM into equal-sized frames (`4 KB`), using a lookup directory (**Page Table**) so any page can sit in ANY free frame anywhere in RAM!
- **Finer points:**
  - **Exact Bit-Splitting Rules:** `VA bits = p (Page #) + d (Offset)`; `PA bits = f (Frame #) + d (Offset)`; `Page Size = Frame Size = 2^d` units!
  - **Decimal Translation Shortcut (`2024_FN_Q50`):** `Page# = VA / PageSize`, `Offset = VA % PageSize`, `PA = Frame# * PageSize + Offset`!
  - **Byte-Addressable vs Word-Addressable (`2019_FN_Q42`):** Number of addresses in a page = `Page Size (bytes) / Word Size (bytes)`!
  - **Page Table Formulas:**
    1. Number of entries = `2^p = Virtual Space / Page Size` (`2025_FN_Q14`!).
    2. PT size = `Entries × PTE_size` (memory overhead! `2021_FN_Q31(C)`).
    3. Pages occupied by PT = `ceil(PT_size / Page_size)`.
  - **Inside One PTE & MMU Responsibilities (`2024_AN_Q28`):** Valid/Invalid bit, R/W/X protection bits, Dirty/Modified, Reference/Accessed. MMU translates VA->PA and raises Page Fault or Protection Fault traps (`2024_AN_Q28(B,C,D)`), while OS allocates new page tables (`A` is OS, not MMU!).
  - **Optimal Page Size Formula (`[SHOULD]`):** $\sqrt{2 \cdot s \cdot e}$.
- **GATE-level items:** Computing max PT entries (`2025_FN_Q14`), decimal VA -> PA (`2024_FN_Q50`), word-addressable distinct VA counts (`2019_FN_Q42`), and MMU vs OS responsibility MSQs (`2024_AN_Q28`).
- **Diagrams needed:** `MEMORY` (VA `[p | d]` -> Page Table lookup -> PA `[f | d]` showing `d` passing straight through unchanged); `MEMORY` (Zoomed-in Page Table Entry showing Valid, R/W, Dirty, Ref bits); `COMPARE` (Byte-addressable vs Word-addressable page offset bits).

#### Lesson 05.3 · TLB, Multi-Level Paging, Inverted/Hashed Page Tables & Segmentation
- **Tag:** `[MUST]` — Massive 2-mark NAT generator (`2026_AN_Q54`, `2025_AN_Q58`, `2024_AN_Q47`, `2023_FN_Q58`, `2022_FN_Q38`, `2021_AN_Q62`).
- **Estimated reading time:** 85 minutes.
- **Prerequisites:** Lesson 05.2.
- **Beginner must-see:** Looking up a Page Table in RAM for every single instruction DOUBLES memory time (`1 access for PT + 1 access for data`), AND a 32-bit/64-bit Page Table can be megabytes/terabytes huge! OS fixes BOTH using two tricks: a tiny super-fast hardware cache for translations (**TLB**) and chopping the giant Page Table into a tree of smaller tables (**Multi-Level Paging**)!
- **Finer points:**
  - **TLB Mechanics (`2022_FN_Q38(A,B)`, `2026_AN_Q54`, `2019_FN_Q42`):**
    - Associative parallel search across all valid entries (`O(1)` hardware).
    - **TLB Reach** = `Number of TLB entries × Page Size` (`2026_AN_Q54`).
    - TLB Entry fields: `ASID/PID + VPN + PFN + Control bits` (round entry bits to bytes when asked total TLB size in bytes, `2026_AN_Q54`!).
    - **TLB Hit + Cache Miss (`2022_FN_Q38(B)`):** If TLB hits, the page MUST already be resident in RAM!
    - **TLB EMAT (without page faults):** `h(t_TLB + t_RAM) + (1 - h)(t_TLB + (L + 1) * t_RAM)` for `L`-level paging!
  - **Multi-Level Paging (`2025_AN_Q58`, `2024_AN_Q47`, `2023_FN_Q58`, `2021_AN_Q62`):**
    - Entries per PT page = `PageSize / PTE_size` -> `k` bits per inner index (`2025_AN_Q58`, `2023_FN_Q58`).
    - When VPN bits aren't divisible by `k`, **outer directory takes the remaining top bits** (`2025_AN_Q58`: `11 + 9 + 12 = 32`!).
    - **Min vs Max Page Table Memory (`2024_AN_Q47`):** Outer dir is 1 page; Min inner pages = `ceil(used_pages / entries_per_inner_page)`; Max inner pages = `min(used_pages, outer_entries)`!
  - **Inverted & Hashed Page Tables (`2022_FN_Q38(C,D)`):**
    - Inverted PT has 1 entry per **Physical Frame** (`PID + VPN`), saving huge RAM on 64-bit systems, yet linear/hash search means access time is **NOT constant** for all VAs (`2022_FN_Q38(C)` is FALSE!), and Hashed PT collision chains vary lookup time (`2022_FN_Q38(D)` is TRUE!).
  - **Segmentation & Segmented Paging (`[SHOULD]`):** `<Segment#, Offset>`, `Offset < Limit` protection check, external fragmentation vs internal paging.
- **GATE-level items:** Computing TLB bytes from TLB reach (`2026_AN_Q54`), outer index bits `b` (`2025_AN_Q58`), levels `L` (`2023_FN_Q58`), `Min + Max` PT pages (`2024_AN_Q47`), and Inverted/Hashed PT properties (`2022_FN_Q38`).

#### Lesson 06.1 · Demand Paging, Page Fault Steps & Combined TLB + Page-Fault EMAT
- **Tag:** `[MUST]` — High-yield 2-mark formulas (`2024_AN_Q12`, `2020_FN_Q37`, `2018_FN_Q20`).

#### Lesson 06.2 · Page Replacement Policies, Belady's Anomaly & 2-D Array Page Faults
- **Tag:** `[MUST]` — Guaranteed bread-and-butter GATE topic (`2025_AN_Q47`, `2025_FN_Q54`, `2023_FN_Q57`, `2022_FN_Q64`, `2017_FN_Q36`).
- **Estimated reading time:** 85 minutes.
- **Prerequisites:** Lesson 06.1, C8 (2-D row-major array memory layout).
- **Beginner must-see:** When all physical RAM frames are full and a new page is needed, the OS must kick one existing page out! Picking the wrong victim causes endless disk swapping — like kicking out the textbook you need 2 minutes later!
- **Finer points:**
  - **All Replacement Algorithms Traced:**
    - **FIFO:** Oldest loaded frame evicted (simple queue, suffers Belady!).
    - **Optimal (Belady's):** Evicts page unused for longest future time; **Bounded-Lookahead Optimal (`2025_FN_Q54`)** looks only `k` steps ahead!
    - **LRU (Least Recently Used):** Evicts oldest last-used timestamp (needs hardware stack/counters).
    - **LFU & MFU (`2025_AN_Q47`):** Count usage frequency (with explicit FIFO tie-breaker rule!).
    - **Second-Chance / Clock (`[SHOULD]`):** Circular queue clearing `R = 1 -> R = 0` before evicting `R = 0`.
  - **Stack Algorithms & Belady's Anomaly (`2017_FN_Q36`):**
    - A policy is a **Stack Algorithm** iff frames kept for `m` frames are always a subset of frames kept for `m+1` frames ($B_t(m) \subseteq B_t(m+1)$).
    - Stack algorithms (**LRU, Optimal**) NEVER suffer Belady's Anomaly; **FIFO, Random (`2017_FN_Q36`), LFU, MFU** do NOT satisfy the stack property and CAN suffer Belady's Anomaly!
  - **C 2-D Array Traversal Page Faults (`2023_FN_Q57`):** Row-major `D[128][128]` walked column-by-column (`D[j][i]`) when `allocated_frames < total_array_pages` causes thrashing on EVERY column pass (`32 × 128 = 4096`)!
- **GATE-level items:** Tracing `4-lookahead Optimal` (`2025_FN_Q54`); identifying which policy produced a given frame snapshot (`2025_AN_Q47`); computing page fault rate `faults / accesses` (`2022_FN_Q64`: `0.6`); 2-D C loop LRU page faults (`2023_FN_Q57`); Random vs LRU Belady's anomaly (`2017_FN_Q36`).
- **Diagrams needed:** `TRACE` (Frame-by-frame reference trace table comparing FIFO, Optimal, LRU, LFU, MFU on the same string); `ARRAY` (`1,2,3,4,1,2,5,1,2,3,4,5` breaking FIFO `3->4` frames while staying nested in LRU); `MEMORY` (`D[128][128]` row-major layout across 32 pages with 30 LRU frames, `2023_FN_Q57`).
- **Hand traces:** Full hand trace of `2025_FN_Q54` (`6` faults), `2022_FN_Q64` (`9/15 = 0.6`), and `2023_FN_Q57` (`4096` faults).
- **Common mistakes:** Counting hits when initial frames are empty (first load into an empty frame IS a page fault!); using frequency *since start of time* without checking if evicted pages reset frequency in LFU/MFU; writing `60` instead of `0.6` for page fault rate (`2022_FN_Q64`); ignoring row-major layout in `D[j][i]` (`2023_FN_Q57`!).

#### Lesson 06.3 · Thrashing, Working Set Model & Copy-on-Write (`fork()`)
- **Tag:** `[SHOULD]` — Important conceptual bridge explaining OS stability and `fork()` efficiency (`2024_AN_Q28(D)`).
- **Estimated reading time:** 50 minutes.
- **Prerequisites:** Lesson 01.2, Lesson 06.2.
- **Beginner must-see:** If you open 50 heavy apps on a 4 GB RAM laptop, every app steals frames from the others — so the CPU spends 99% of its time waiting for disk swaps (**Thrashing**), and everything freezes!
- **Finer points:**
  - **Thrashing Curve:** Degree of Multiprogramming vs CPU utilization; Local vs Global frame replacement.
  - **Working Set Model ($\Delta$):** Sum of all active working sets $D = \sum WSS_i$; if $D > m$ (total physical frames), OS suspends a process!
  - **Page-Fault Frequency (PFF):** High fault rate -> add frame; low fault rate -> take away frame.
  - **Copy-on-Write (COW):** Why `fork()` doesn't copy 2 GB of RAM immediately — parent & child share frames marked **Read-Only**, triggering a trap (`2024_AN_Q28(D)`) to copy ONLY the modified page on first write!
- **GATE-level items:** Identifying thrashing symptoms & Working Set allocation formulas; how read-only PTE trap implements COW `fork()`.
- **Diagrams needed:** `TIMELINE` (Degree of Multiprogramming vs CPU Utilization U-turn curve + Working Set sliding window $\Delta$); `FRAMES` (Parent & Child sharing read-only frames -> Child writes -> MMU trap -> private copied frame!).
- **Hand traces:** Computing Working Set sizes $WSS(t)$ across a 12-page trace with window $\Delta = 4$; checking if 3 processes fit in 10 frames.
- **Common mistakes:** Thinking raising multiprogramming ALWAYS improves CPU utilization; thinking `fork()` physically copies every RAM frame upfront.

#### Lesson 07.2 · Disk Geometry, Access Time & Disk Scheduling Algorithms (`RAID` Note)
- **Tag:** `[MUST]` — Regular 2-mark NATs (`2026_FN_Q59`, `2024_AN_Q61`, `2024_FN_Q39`, `2020_FN_Q40`, `2018_FN_Q63`).

- **Beginner must-see:** Inside a spinning hard disk, multiple magnetic platters sit stacked like pancakes on one spindle, and **ONE shared mechanical arm** slides in and out across all platters together!   - **3-D Geometry (`2024_FN_Q39`, `2018_FN_Q63`):** Platter, Surface (`2` per platter if double-sided!), Track, Sector, **Cylinder** (same track across all surfaces). `Disk Capacity = Surfaces × Cylinders × Sectors/Track × Bytes/Sector`!

    1. **Seek Time:** moving arm across cylinders (given avg or `tracks × ms/track`).
    2. **Rotational Latency:** spinning desired sector under head (`avg = 0.5 × (60 / RPM)`!).
    3. **Transfer Time:** reading sector bytes (`(bytes_read / track_bytes) × rotation_time`).
    - **Random vs Sequential Sectors (`2026_FN_Q59` vs `2024_AN_Q61`):** 10 random sectors on a track each pay `avg rot latency + sector transfer` (unless stated otherwise)!

    - **Direction Reversals (`2018_FN_Q63`)** & initial head direction!
  - **RAID Levels 0, 1, 5 (`[LATER]`):** Striping, mirroring, distributed parity (`N - 1` usable disks).
- **GATE-level items:** Cylinder counting (`2024_FN_Q39`), multi-track random-sector transfer time (`2026_FN_Q59`, `2024_AN_Q61`), SSTF power + reversal counting (`2018_FN_Q63`), SSTF sequence traps (`2020_FN_Q40`).
- **Diagrams needed:** `MEMORY`/3-D sketch (Stacked platters, single shared actuator arm, highlighted Cylinder); `TIMELINE` (1-sector I/O: Seek + Rot Latency + Transfer); `GRAPHPIC` (Cylinder ruler `0..199` plotting zig-zags for SSTF, SCAN, LOOK, C-SCAN, C-LOOK with reversal arrows circled).

- **Common mistakes:** Trying to seek across platter numbers (`2018_FN_Q63`!); missing SSTF turning back up at `72 -> 116` (`44` < `52`, `2018_FN_Q63`!); using `1 ×` instead of `0.5 ×` rotation time for average rotational latency; forgetting `SCAN` hits `0`/`199` while `LOOK` stops at the extreme request.

  2. Given `t_TLB = 10 ns`, `t_RAM = 80 ns`, `TLB hit = 90%`, `page fault = 0.01%` of **all** memory accesses (`5 ms` clean, `50%` dirty), compute EMAT in ns (`NAT`).
  3. Explain why a page fault handler restarts the faulted instruction rather than skipping to `PC + 4` (`MCQ`).
- **Lesson 06.2 (`Page Replacement, Belady & 2-D Array Loops`):**
  1. Trace `1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5` on `3` frames vs `4` frames under **Clock (Second-Chance)** and count faults (`NAT`).
  2. Contrast faults of row-major `A[i][j]` vs column-major `A[j][i]` for `int A[64][64]` (`1 KB` page, `4 B` int, `10` LRU frames) (`NAT`).
  3. Which replacement policies among FIFO, Clock, LRU, LFU, Optimal, and MRU satisfy the Stack Property and avoid Belady's Anomaly? (`MSQ`).
- **Lesson 06.3 (`Thrashing, Working Set & Copy-on-Write`):**
  1. Given reference string and Working Set window $\Delta = 4$, find the total frames required by 3 concurrent processes at time `t = 8` (`NAT`).
  2. After `fork()`, a parent with `1000` mapped pages writes to `12` pages while child writes to `8` *other* pages under Copy-on-Write: how many total physical frames hold data now? (`NAT`).
  3. Identify symptoms and remedies for Thrashing (lowering multiprogramming vs adding more frames vs swapping vs increasing quantum) (`MSQ`).

### Chapter 07 · File Systems and Disk
- **Lesson 07.1 (`Files, Directories, Allocation & Inodes`):**
  1. Compute total blocks needed for a **Free-Space Bitmap** on a `128 GB` disk with `4 KB` blocks (`NAT`).
  2. A Unix Inode has `10` direct, `1` single, `1` double, and `1` triple indirect pointers (`1 KB` block, `4 B` ptr): find the block-offset range served by double indirect pointers (`MCQ`).
  3. Compare Hard Link vs Soft Link behaviour when the original file is deleted and recreated with the same filename (`MSQ`).
- **Lesson 07.2 (`Disk Geometry, Access Time & Disk Scheduling`):**
  1. Compute total cylinder movements for `SCAN` vs `LOOK` vs `C-SCAN` (counting return sweep vs not counting) on request queue `[98, 183, 37, 122, 14, 124, 65, 67]` starting at `53` moving down (`NAT`).
  2. Compare reading `100` **contiguous** sectors on the same track vs `100` **random** sectors on the same track at `7200 RPM` (`NAT`).
  3. Given 5 data disks of `2 TB` each under RAID-0, RAID-1 (mirrored pairs), and RAID-5, compare usable capacity and single-disk fault tolerance (`MSQ`).

## PART 8. WHAT IS MISSING FROM THE SUBJECT

Looking across the official GATE CS Operating Systems syllabus, `Part C` (78 PYQs), Galvin/OSTEP, Made Easy, and GateWallah, these topics are missing or buried without explicit coverage in `Part B.2`'s 7-chapter list:

1. **Chapter 00 (Dual Mode, Privileged Instructions, Interrupts vs Traps vs Exceptions & C Library vs Syscalls):** Completely omitted from `Part B.2`, yet directly tested (`2023_FN_Q23`, `2021_FN_Q60`, `2024_AN_Q12`).
2. **Wrong Order of Chapter 01 (`Deadlock` before `Processes` and `Sync`):** Placing Deadlock first only because it is free breaks zero-level dependency (`Processes/Locks -> Deadlock`).
3. **`fork()` Loop/Short-Circuit Trees, `wait(NULL)`, `exec()`, Zombie/Orphan & Thread Shared-vs-Private Memory (`P1/P2` vs `T1/T2`):** Absent from `Part B.2` details, yet tested in almost every Process/Thread question (`2026_FN_Q63`, `2024_FN_Q53`, `2024_FN_Q12`, `2023_FN_Q22`, `2021_AN_Q41`, `2019_FN_Q29`, `2017_AN_Q14`, `2017_FN_Q25`).
4. **Inter-Process Communication (IPC: Shared Memory, Message Passing, Pipes):** Named in `Part B.1` syllabus line, missing from `Part B.2` chapters.
5. **CPU Scheduling Edge Topics:** Multi-processor scheduling (`2025_FN_Q38`), CPU-I/O loop Ready Queue entries (`2025_FN_Q29`), RR queue tie-breaking & context-switch rules (`2022_FN_Q42`), exponential burst prediction, `1 - p^n` CPU utilization, MLFQ, and Real-Time (RMS/EDF).
6. **Synchronization Depth:** Non-atomic `LOAD/ADD/STORE` min/max interleavings (`2023_FN_Q38`, `2021_FN_Q59`, `2019_FN_Q32`), Peterson's / `TSL` / `CAS` with 3 CS criteria, Barriers (`2020_FN_Q38`), Monitors (Hoare vs Mesa), Spinlocks vs Sleep-Mutex, Priority Inversion, Livelock (`2021_AN_Q13`).
7. **Memory & Paging Finer Math:** Word-addressable paging (`2019_FN_Q42`), TLB Reach (`2026_AN_Q54`), Non-divisible multi-level paging (`2025_AN_Q58`) & Min/Max demand-paged PT pages (`2024_AN_Q47`), Inverted vs Hashed PT lookup costs (`2022_FN_Q38`), Segmentation/Segmented Paging, Optimal Page Size, and explicit flagging of COA Memory Interfacing crossovers (`2023_FN_Q42`).
8. **Virtual Memory Depth:** Limited-lookahead Optimal (`2025_FN_Q54`), LFU/MFU/Clock policies (`2025_AN_Q47`), Stack Property proof of Belady's Anomaly (`2017_FN_Q36`), 2-D C Array traversal page faults (`2023_FN_Q57`), Dirty-page EMAT conditional probability warning (`2020_FN_Q37`), Thrashing, Working Set, and Copy-on-Write (`fork()`).
9. **File Systems & Disk Mechanics:** Linear directory full-scan rule (`2021_FN_Q34`), Unix Inodes (`2019_FN_Q63`), Linked free-list pointer overhead (`2026_AN_Q53`), Linked-allocation internal waste (`2025_FN_Q51`), Middle-insert disk I/O (`2022_FN_Q63`), 3-D disk geometry (`2024_FN_Q39`), 0-seek platter switching & reversal power costs (`2018_FN_Q63`), Random vs sequential sector reads (`2026_FN_Q59`, `2024_AN_Q61`), SCAN vs LOOK / C-SCAN vs C-LOOK, Hard vs Soft links, Journaling/`fsck`, and RAID basics.
